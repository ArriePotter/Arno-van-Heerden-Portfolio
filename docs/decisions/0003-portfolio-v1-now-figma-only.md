# 0003: Start portfolio v1 now, Figma-only, alongside roadmap Stage 1

- **Date:** 2026-10-03
- **Status:** Accepted (brief approved 2026-10-03)
- **Department:** Product strategy
- **Phase:** Brief
- **Decided by:** Arno

## Context

The career roadmap schedules the portfolio site for Stage 5 (Jun–Jul 2027). Arno wants to start now. Visual fundamentals (Stage 1, 19 Oct – 13 Dec) haven't been learned yet. Available time is about 25 h a week: 3 h on each weekday and 5 h on each weekend day.

## Options considered

1. **Wait for Stage 5,** as the roadmap planned.
   - Cons: loses months of process evidence and motivation.
2. **Build the full site now.**
   - Cons: it would be visually designed before the visual fundamentals are learned, which means rework and a weaker result.
3. **Do v1 now as structure and words only,** in Figma, and add the visual layer after Stage 1.
   - Pros: follows the roadmap's order of learning, gives Stage 1 a real practice project, and starts the process record now.

## Decision

Option 3. **v1 = Figma only:**

- information architecture
- wireframes
- real copy
- component skeleton
- a handoff spec for the front end

Case studies appear as placeholders that show where and how they will sit. There is no live site, domain or backend in v1. The appetite is **8 weeks** (about 3 Oct – 28 Nov 2026), with scope adjusted to fit the time, not the other way round. The visual layer (v2) follows once Stage 1's exit criteria are met.

## Evidence

- Shape Up (fixed time, variable scope).
- The lifecycle rule that no build starts before a "Ready for dev" design exists (`docs/lifecycle.md`).
- The roadmap's order of learning.

## Consequences

- The roadmap order changes: the portfolio starts in Stage 0/1 instead of Stage 5. The roadmap's hour plan must be rebalanced (see the brief, *Appetite*).
- v1 can only be validated through Figma prototypes, not live analytics.
- Every version is captured as named Figma versions and decision records, so the v1 → vN evolution can be shown later.
